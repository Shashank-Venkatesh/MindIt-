# MindIt! API — Setup & Run Guide

This is a **FastAPI** backend ("MindIt! API") that turns raw text/documents into
structured notes. It uses **Supabase** for auth and Postgres storage.

## 1. Prerequisites

- Python 3.10+ (3.12 recommended — the shipped `.pyc` cache files are for 3.12/3.14)
- pip
- A Supabase project (free tier is fine) — https://supabase.com
- (Optional) A virtual environment tool: `venv`, `conda`, etc.


## 2. Create a virtual environment (recommended)

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
```

## 3. Install dependencies

```bash
pip install -r requirements.txt
```

## 4. Configure environment variables

Copy the example env file and fill in your own Supabase credentials:

```bash
cp .env.example .env
```

Then edit `.env`:

```
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_ANON_KEY=your-anon-key
SUPABASE_JWT_SECRET=your-jwt-secret
DATABASE_URL=postgresql://postgres:YOUR_DATABASE_PASSWORD@db.your-project-ref.supabase.co:5432/postgres
PORT=4000
```

Where to find these in Supabase:
- `SUPABASE_URL` / `SUPABASE_ANON_KEY` → Project Settings → API
- `SUPABASE_JWT_SECRET` → Project Settings → API → JWT Settings
- `DATABASE_URL` → Project Settings → Database → Connection string (URI), with your DB password filled in

> ⚠️ Never commit your real `.env` file — it contains secrets. Only `.env.example` should be shared/committed.

## 5. Run the server

From inside the `server/` directory (with the virtualenv active):

```bash
uvicorn app.main:app --reload --port 4000
```

- `--reload` auto-restarts on code changes (great for local dev)
- The app also reads `PORT` from `.env`, but `uvicorn`'s `--port` flag on the command line takes precedence over that, so keep the two in sync if you change one

On startup, the app automatically creates any missing database tables (see `app/database.py` — dev-friendly; use real migrations for production). It also enables the `pgvector` Postgres extension and creates the `heading_embeddings` table + similarity index used for mind-map link suggestions (see [Vector search / graph-link suggestions](#11-vector-search--graph-link-suggestions) below).

## 6. Verify it's running

Open in a browser or use curl:

```bash
curl http://localhost:4000/
```

Expected response:
```json
{"name": "MindIt! API", "status": "running", "docs": "/docs"}
```

Interactive API docs (Swagger UI) are auto-generated by FastAPI at:
```
http://localhost:4000/docs
```

## 7. Test the API endpoints

### Health check
```bash
curl http://localhost:4000/api/health
```
Expected: `{"status": "ok"}`

### Process raw note text (core model/processing endpoint)
```bash
curl -X POST http://localhost:4000/api/process \
  -H "Content-Type: application/json" \
  -d '{"text": "Meeting notes: discuss Q3 roadmap, assign owners, follow up next week."}'
```
This runs your text through `app/processor.py` and returns the structured result. No auth required.

### Notes history (requires Supabase auth token)
```bash
curl http://localhost:4000/api/notes \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>"
```
Without a valid token you'll be treated as a "guest" user or receive a 401, depending on the route (see `app/auth.py`).

### Documents
```bash
curl http://localhost:4000/api/documents \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>"
```

### Profile (requires auth)
```bash
curl http://localhost:4000/api/profile/me \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>"
```

To get a `SUPABASE_ACCESS_TOKEN` for testing, sign up/sign in a test user through Supabase Auth (e.g. via the Supabase JS client in a small script, or the Supabase dashboard's Auth section) and copy the resulting access token.

## 8. Connecting a frontend

CORS is currently pre-configured (in `app/main.py`) to allow only:
- `http://localhost:5173`
- `http://127.0.0.1:5173`

(the default Vite dev server ports). If your frontend runs elsewhere, add its origin to the `ALLOWED_ORIGINS` list in `app/main.py`.

## 11. Vector search / graph-link suggestions

MindIt! suggests links between mind-map headings (even across different notes)
using vector similarity search. No third-party vector DB account is needed —
it runs on **pgvector**, an extension of the same Supabase Postgres database
you already configured above.

- **Embeddings**: generated locally by `app/services/embeddings.py`, reusing
  the app's existing hashed-IDF embedder (`app/processor.py::build_embedding`,
  48 dimensions). Nothing is sent to an external embedding API.
- **Storage/search**: `app/models.py::HeadingEmbedding` is a table with a
  `vector(48)` column, queried with pgvector's cosine-distance operator
  (`<=>`). Enabled automatically on startup by `app/database.py`; a
  standalone SQL version lives at
  `server/migrations/0001_pgvector_heading_embeddings.sql` if you'd rather
  run it manually via the Supabase SQL editor.

### Endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/embeddings/index` | Embed + upsert a note's headings. Call whenever a note is saved. |
| `POST` | `/api/embeddings/suggestions` | Get top-N similar headings (candidate graph edges) for one heading. |
| `DELETE` | `/api/embeddings/note/{note_id}` | Remove a note's heading embeddings (called automatically on note delete). |

Example:
```bash
curl -X POST http://localhost:4000/api/embeddings/index \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>" \
  -d '{"note_id": "abc123", "headings": [{"id": "h1", "text": "Cellular Respiration"}]}'

curl -X POST http://localhost:4000/api/embeddings/suggestions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <SUPABASE_ACCESS_TOKEN>" \
  -d '{"note_id": "abc123", "heading_id": "h1", "limit": 5, "threshold": 0.75}'
```

Suggestions are scoped per-user (`owner`), so one user never sees another
user's headings.

## Troubleshooting

| Issue | Fix |
|---|---|
| `pydantic_settings.exceptions.ValidationError` on startup | One or more required env vars are missing from `.env` — check all four required keys are set |
| `psycopg2` install fails | Install PostgreSQL client build tools (`sudo apt install libpq-dev` on Debian/Ubuntu, or use `psycopg2-binary`, which is already what's pinned here) |
| CORS errors from browser | Add your frontend's origin to `ALLOWED_ORIGINS` in `app/main.py` |
| 401 on `/api/notes`, `/api/documents`, `/api/profile/me` | You need a valid Supabase `Authorization: Bearer <token>` header |
| Port already in use | Change `--port` in the uvicorn command and/or `PORT` in `.env` |
